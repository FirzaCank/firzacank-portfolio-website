## Context

A mining contractor running large Komatsu excavators (PC2000, PC1250, PC850 class) needed forward visibility into cylinder and hose rehousing demand. Lifetime data lived in the maintenance planner's workbooks, indexed by EGI (unit serial), section (boom, arm, bucket), and part number. Stock for overhaul (stock OVH) was tracked separately — the only way to confirm parts were ready when a cylinder hit its rehousing window was a manual cross-check.

## Problem

- Lifetime data sat across multiple sheets per excavator class, with serial ranges (`20196-20453`, `20454-UP`) deciding which part number applied. Manual lookups were error-prone.
- "Need per cylinder" vs "stock OVH" was a per-row Excel calc with no aggregated view to flag shortages before they hit scheduling.
- Planning wanted one screen showing which unit needs what part next, but the source data was structured for parts catalogs, not forward planning.

## Approach

1. Restructured the source workbooks into a clean tabular dataset — one row per unit + section + component + part number, stock and need columns aligned, serial-range logic flattened for clean downstream joins.
2. Built a parts-demand model in Sheets combining current lifetime status with the rehousing interval per cylinder type, producing a forward window of which units come due next month, quarter, and year.
3. Designed a Looker Studio dashboard with three lenses — fleet-level readiness (parts ready vs shortage), per-unit timeline (next milestone per EGI), and part-level (where stock is below need).
4. Added an exception view surfacing rows where stock OVH is zero against an upcoming need, so the planner acts on a shortlist instead of scanning the whole workbook.
5. Documented a lightweight monthly refresh so the planner updates the source sheet and the dashboard stays in sync.

## Outcome

The dashboard replaced ad-hoc spreadsheet lookups with a single planning view the maintenance team uses in monthly reviews. Forward visibility let procurement order against an actual list of upcoming jobs instead of buffer-stocking everything, and the exception view turned shortage detection from a periodic audit into a daily check.
